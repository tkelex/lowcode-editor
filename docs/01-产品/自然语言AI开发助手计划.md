# 自然语言 AI 开发助手计划

## 目标

把当前低代码编辑器升级为“自然语言驱动的页面开发助手”。用户用一句话描述目标，AI agent 能理解意图、选择合适工具、生成或修改低代码 schema，并在用户确认后写入编辑器。

最终体验不是让用户手动选择一堆技术参数，而是让用户表达需求：

- “帮我做一个用户管理页，接口是 `/api/users`，要有列表、新增、编辑、详情。”
- “把当前选中的卡片改得更像后台数据看板。”
- “给提交按钮接上 `POST /api/orders`。”
- “这个页面表格太乱，帮我优化布局和字段展示。”

系统应把这些自然语言请求路由到不同 agent 能力，并保持可预览、可撤销、可验证。

## 当前基础

已具备的基础能力：

- 编辑器内已有 `AI 搭建` 面板，可提交自然语言 prompt。
- 后端已有 AI 页面生成接口和 AI agent run 接口。
- Agent 会读取当前组件树、选中组件、物料能力和数据源上下文。
- Agent 候选结果会先展示摘要、执行轨迹、warnings、assumptions 和预览，再由用户确认应用。
- CRUD/数据源类请求已优先路由到确定性 CRUD 生成器，而不是让模型自由拼复杂 schema。
- CRUD 生成器输出普通 Page schema，继续复用现有编辑、保存、版本和发布链路。

## 产品原则

- 自然语言优先：用户先描述目标，系统再判断意图和工具。
- 确定性优先：能用规则生成器、校验器、patch 工具解决的，不依赖模型自由发挥。
- 用户确认优先：AI 只产出候选结果，不直接保存、发布或覆盖用户页面。
- 局部修改优先：用户选中组件时，默认理解为修改当前上下文，避免整页误覆盖。
- 可解释优先：每次 agent 执行都要展示识别意图、工具调用、影响范围、风险提示和应用结果。
- 安全优先：前端不持有模型 API key，AI 默认不生成 custom JS，发布态保持 `allowCustomJS=false`。

## 能力路线图

### P0：统一自然语言入口

目标：把 `AI 搭建` 面板从“页面生成表单”升级为“自然语言开发助手”。

交付物：

- 主输入框作为唯一核心入口，支持页面生成、局部修改、样式优化、事件绑定、数据源绑定等描述。
- 保留高级选项，但弱化为可折叠配置：目标范围、接口说明、响应示例。
- 默认按钮改为 `让 Agent 处理`，普通草稿生成作为次级能力。
- 面板内展示“识别意图”和“影响范围”。
- 命中 CRUD 时明确展示“已使用确定性 CRUD 生成器”。

验收标准：

- 用户输入 CRUD 请求后，页面展示 CRUD 候选、预览和应用按钮。
- 用户输入非 CRUD 修改请求后，页面展示 patch 候选、预览和应用按钮。
- 用户不需要理解 schema、patch、dataSources 等内部概念，也能完成一次生成或修改。

### P1：Agent 意图路由中心

目标：把当前 CRUD 判断扩展为统一的意图路由层。

建议意图类型：

| 意图 | 说明 | 首选工具 |
| --- | --- | --- |
| `crud-page` | 根据接口或数据源模型生成管理页 | CRUD 生成器 |
| `free-page` | 生成普通页面或区块 | AI schema draft + validate |
| `edit-selected` | 修改当前选中组件或容器 | schema patch |
| `style-polish` | 优化样式、布局、视觉层级 | schema patch |
| `bind-data-source` | 给组件绑定页面数据源 | data source patch |
| `add-event-action` | 给按钮、表单、链接配置事件 | event action patch |
| `fix-page-issue` | 修复校验错误、空态、数据绑定问题 | diagnostic + patch |

交付物：

- 新增 agent route 决策结果：`intent`、`confidence`、`reasons`、`fallback`。
- 前端在执行轨迹中显示 route 决策。
- 低置信度请求进入澄清或保守 patch，不直接整页替换。
- 为每类意图补最小单测和 1 条人工验收用例。

验收标准：

- “做用户管理页”进入 `crud-page`。
- “把选中按钮改成主要按钮并加跳转”进入 `edit-selected` 或 `add-event-action`。
- “优化这个页面视觉效果”进入 `style-polish`。
- “营销首页首屏”不误进 `crud-page`。

### P2：工具箱扩展

目标：让 agent 不只会生成整页，还能完成低代码开发中最常见的编辑任务。

优先工具：

- 组件局部修改工具：按组件 ID 修改 props、styles、children。
- 事件动作工具：生成 `props.onEvent[eventName].actions`。
- 数据源绑定工具：生成 Page `dataSources`，并把组件 `dataSourceId` 绑定到对应数据源。
- 样式优化工具：在物料白名单和样式 setter 范围内优化布局、间距、字号、颜色。
- 页面诊断工具：检查组件树、数据源、事件动作、空态和发布安全风险。

验收标准：

- Agent 能给按钮添加 URL、toast、http、confirm 等事件动作。
- Agent 能把 Table/List/Select 绑定到页面数据源。
- Agent 能只修改选中容器内部结构，不影响无关区域。
- 所有工具输出应用前都必须经过现有 schema/patch 校验。

### P3：对话式迭代体验

目标：让用户像和开发助手协作一样连续修改页面。

交付物：

- 保留当前页面会话历史，用于下一次 agent run。
- 支持“继续修改刚才的结果”“撤回上一步”“只应用其中一部分”。
- 执行轨迹聚合为用户能理解的步骤：读取上下文、识别意图、调用工具、校验候选、等待确认。
- 候选结果显示差异摘要：新增组件、修改组件、删除组件、影响范围。

验收标准：

- 用户连续输入 3 次修改请求，agent 能基于当前页面状态继续工作。
- 用户能区分“预览结果”和“已应用结果”。
- 应用失败时能看到明确原因，不出现静默失败。

### P4：可发布的自然语言开发闭环

目标：从自然语言生成到保存、版本、发布形成完整主链路。

交付物：

- Agent 应用成功后提示保存页面。
- 保存后自动产生版本记录和审计摘要。
- 发布前执行安全检查：custom JS、外部 URL、数据源配置、事件动作。
- 为自然语言生成 CRUD 页面补 e2e 回归。

验收标准：

- 用户能从一句自然语言开始，生成页面、确认应用、保存、发布，并访问发布结果。
- 发布页运行态能请求配置的数据源并渲染表格或详情。
- 发布态不执行未授权 custom JS。

## 近期执行顺序

1. 改造 `AI 搭建` 面板文案和交互，让 `Agent 修改` 成为主入口。
2. 在 agent run 返回值中补充统一 route 决策信息：意图、置信度、原因。
3. 前端展示 route 决策卡片，CRUD 命中时明确标记确定性生成器。
4. 把 CRUD 路由测试扩展为通用意图路由测试。
5. 新增 `add-event-action` 工具，优先支持按钮 click 和表单 finish。
6. 新增 `bind-data-source` 工具，优先支持 Table/List/Select。
7. 做一条 e2e：自然语言生成用户管理页 -> 预览 -> 应用 -> 保存。

## 风险和边界

- 不让 AI 直接保存、发布、删除页面。
- 不让 AI 绕过编辑器 store、版本、发布和审计链路。
- 不让前端保存或发送模型 API key。
- 不把数据源模型理解成平台托管业务数据表；当前只描述外部 API。
- 不默认生成 custom JS；必须显式开启并在发布态禁用。
- 不在低置信度时整页替换，优先要求确认或生成局部候选。

# 物料体系说明

本文记录当前内置物料和扩展约定。实际能力以 editor registry、runtime registry 和 schema registry 为准。

## 已内置物料

### 布局和基础

- 布局容器：Container、Card、Space、Flex、Grid。
- 基础组件：Button、Link、Icon、Text、Image、Divider、Tabs、Steps。

### 表单

- 表单容器：Form、FormItem。
- 独立表单控件：Input、Textarea、Select、Radio、Checkbox、DatePicker、Switch、Upload、Rate。
- FormItem 支持 input、textarea、date、select、radio、checkbox、switch、rate。
- Form 支持提交、重置、值变化事件，并暴露 submit、reset、getValues、setValues 方法。

### 数据展示

- Table、TableColumn。
- List、Descriptions、Statistic、Pagination、Chart。
- Table 支持静态 JSON 数据、远程 URL 数据源、分页、空状态、日期列和操作列。
- Chart 当前使用轻量 CSS 条形图实现，后续接入 ECharts 或 AntV 时可以保持同一 schema。

### 反馈

- Alert、Modal、Drawer、Tooltip、Popover、Notification、Result、Empty。
- Modal 和 Drawer 都暴露 open、close 方法，可通过事件动作里的组件联动打开或关闭。

## 常用模板

物料区模板已包含：

- 内容展示区。
- 基础表单。
- 数据卡片。
- 表单页。
- 详情页。
- 列表页。
- 弹窗表单。
- 仪表盘。

模板会生成完整组件树并补齐 parentId，仍然走统一保存、预览、发布和 schema 校验链路。

## 新增物料约定

1. 编辑态 dev 实现放在 `apps/editor-web/src/features/editor/materials/`。
2. 运行态 prod 实现放在 `packages/lowcode-runtime/src/materials/`。
3. 可接收子组件的物料必须接入 `useMaterialDrop`，并在 editor registry 和 schema registry 同步 `acceptsChildren`。
4. editor registry 配置 `category`、`icon`、`keywords`、`sort`、setter、events 和 methods。
5. prod 实现必须过滤低代码内部字段，并转发 registry 声明的事件 props。
6. 修改后运行 `npm run check:editor-props`、`npm run test` 和相关 E2E。

## 远程物料契约（M4）

远程物料是项目 owner 明确信任的客户端代码，不是任意第三方代码沙箱。M4 建立 manifest、宿主注册协议、项目存储和页面版本固定；M5 提供独立示例包；M6 完成 editor/publisher 浏览器 loader、物料区接入、SRI 与错误降级。NestJS 与 Next.js 服务端不得执行远程 JavaScript，CSP 仍由实际部署响应头负责。

manifest 使用协议版本 `1`，包版本必须是 `x.y.z` 固定版本，不能使用 `latest` 或版本范围：

```json
{
  "protocolVersion": "1",
  "name": "@portfolio/customer-materials",
  "version": "1.2.0",
  "entry": "./customer-materials.iife.js",
  "integrity": "sha384-...",
  "schemaVersion": "1.0.0",
  "dependencies": {
    "react": "^18.3.1 || ^19.0.0",
    "reactDom": "^18.3.1 || ^19.0.0",
    "antd": "^5.20.0"
  },
  "materials": [
    {
      "name": "CustomerSummary",
      "displayName": "客户摘要",
      "category": "data",
      "allowedParents": ["Page", "Container"]
    }
  ]
}
```

约束：

- `name + version` 是不可变版本坐标；同版本不能原地替换 entry、integrity 或组件声明。
- `entry` 在安装时解析为相对 manifest URL 的绝对 HTTP/HTTPS 地址，URL 不能携带用户名或密码。
- `integrity` 只接受 `sha256/sha384/sha512` SRI 格式。
- `materials[].name` 在内置物料和项目所有启用远程包之间全局唯一。
- `allowedParents` 把远程子物料加入指定父物料的 schema 约束；`acceptsChildren` 声明远程容器可接收的子物料。
- 服务端只读取持久化后的 manifest 摘要构建动态 registry，不依赖保存或发布时临时访问 CDN。
- 共享依赖版本允许用 `||` 声明明确的兼容主版本；示例物料同时支持编辑器 React 18 和 Next.js App Router 客户端 React 19。宿主会把 canary/prerelease 版本按其 `major.minor.patch` 做兼容判断，但仍拒绝未声明的主版本。

远程 IIFE 通过 `window.__LOWCODE_MATERIAL_HOST__` 注册。宿主提供唯一 React、ReactDOM 和 Ant Design 实例；`register` 校验受信任包坐标、协议、schema、共享依赖版本、manifest 与 bundle 组件声明、运行时组件名冲突。同一 `name@version` 重复注册返回 `already_registered`，不会重复改写 registry。

项目远程物料记录保留所有已安装版本，但同一项目同一包只能有一个 `enabled` 版本。页面保存根据组件树实际使用情况，把完整 `PageMaterialDependency[]` 写入 `Page.materialDependencies` 和新建的 `PageVersion.materialDependencies`；项目升级不会修改旧版本快照。发布和回滚会重新检查目标固定版本仍处于启用状态。

## 示例远程物料（M5）

`apps/remote-material-example` 独立构建 `@portfolio/remote-material-example@1.0.0`，产物为：

- `dist/remote-material-example.iife.js`：通过 `window.__LOWCODE_MATERIAL_HOST__` 注册 `CustomerMetricCard`。
- `dist/manifest.json`：构建后按 entry 最终字节生成 SHA-384 integrity。
- bundle 内的 `editorMaterials.CustomerMetricCard`：提供独立 dev 包装、prod 组件、默认属性、setter、`action` 事件、`reset` 方法和子节点能力；M6 loader 会从宿主注册结果读取并合并进编辑器 registry。

组件通过宿主 React hook 和 Ant Design 实例渲染，包自身只把 `react`、`react-dom`、`antd` 声明为 peer dependency。构建与本地模拟 CDN：

```powershell
npm run build:remote-material-example
npm run serve:remote-material-example -- --host 127.0.0.1 --port 4174
```

静态服务为 manifest 和 entry 返回 CORS header；它不执行安装、allowlist、浏览器 SRI 校验或失败降级。

## 客户端远程加载（M6）

`@lowcode/runtime/client` 暴露 `createRemoteMaterialLoader`。调用方只传固定 `PageMaterialDependency`，loader 内部负责：

- manifest 与 entry 必须同时通过 origin allowlist；非 `localhost`、`127.0.0.1`、`[::1]` 的 HTTP 来源会被拒绝。
- 重新获取 manifest、按共享 schema 规范化，并与固定依赖比较；版本、entry、integrity、依赖或组件声明漂移都会失败。
- entry 有 integrity 时先获取字节并用 Web Crypto 校验，再注入带 `integrity` 和 `crossOrigin="anonymous"` 的 `<script>`，由浏览器继续执行 SRI。
- 同一 `packageName@version + entry` 共享 Promise；失败会清理缓存，允许修复来源后重试。
- 错误使用稳定 code 区分来源、协议、manifest、entry、integrity、注册缺失和超时。

编辑器读取项目全部历史物料记录后只加载 `enabled` 版本，成功时批量替换远程 registry 并扩展 manifest 声明的父物料接收关系；切换项目会清理旧配置。远程定义未就绪或失败时，组件树不会被删除，画布显示可选择的稳定占位，预览在依赖就绪前不会运行。

Publisher 只使用发布版本自己的 `materialDependencies`。服务端仍只迁移和校验快照元数据，客户端依赖全部注册成功后才渲染 `PageRuntime`；失败时输出访客错误页，不回退到项目当前版本。

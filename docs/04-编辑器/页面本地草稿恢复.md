# 页面本地草稿恢复

编辑器会在 owner 或 editor 修改组件树后，将尚未保存到服务端的内容防抖写入浏览器 `localStorage`。本地草稿只用于意外刷新或重新打开页面后的恢复，不会自动调用页面保存接口，也不会改变公开发布快照。

## 作用域与存储

- 存储 key 为 `lowcode-editor:draft:<userId>:<projectId>:<pageId>`，草稿按用户、项目和页面三层隔离。
- 持久化内容包含组件树、存储版本、服务端基线指纹、服务端更新时间、本地修改时间和 dirty 标记。
- 只有组件树变化触发写入；选中组件、撤销重做历史、编辑/预览模式等 UI 状态不持久化。
- viewer 不读取或写入本地草稿。

## 恢复规则

重新打开页面时，编辑器先读取并迁移服务端 schema，再校验同作用域的本地草稿：

1. 草稿无效、版本不支持或组件树校验失败时，移除该记录并使用服务端版本。
2. 草稿与当前服务端组件树一致时，移除冗余记录并直接使用服务端版本。
3. 草稿包含未保存变化时，由用户选择“恢复本地草稿”或“使用服务端版本”。
4. 草稿产生后服务端基线发生变化时，恢复弹窗展示风险提示；恢复仍只写入编辑器 store，不自动覆盖服务端。

## 生命周期

- 手动保存成功后清理本地草稿，并以保存结果作为新基线。
- 保存请求期间产生的新修改不会随旧请求成功而被清理；系统会立即以保存结果为新基线保留这些修改。
- 发布流程中的页面保存成功后同样更新基线；即使后续发布失败，已经成功保存的页面也不再视为未保存草稿。
- 回滚成功后以回滚结果作为新基线，后续编辑不会被误判为基于旧服务端版本。
- 保存失败时保留本地草稿，以便刷新后恢复。

## 验证

- 仓库接口：`node --test scripts/test/page-draft-repository.test.mjs`
- 编辑器行为：`npm run test:e2e:editor`

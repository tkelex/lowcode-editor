## 核心流程

1. 注册或登录。
2. 创建项目和页面。
3. 添加物料并配置属性、样式和事件。
4. 进入预览并退出。
5. 保存后刷新，确认组件树恢复。
6. 使用同一 `expectedRevision` 连续保存两次，确认第二次返回 `409 PAGE_DRAFT_CONFLICT`，页面内容和版本数不变。
7. 在编辑器冲突弹窗分别验证保留本地草稿、重新加载服务端版本，以及发布前保存冲突时不继续发布。
8. 查看版本、回滚并再次保存，确认回滚递增 revision。
9. 发布并通过独立 publisher 访问匿名页面。
10. 修改草稿，确认公开页仍保持旧快照。
11. 再次发布，确认公开页更新。

## 权限

- owner 可管理成员和项目审计。
- editor 可编辑、保存和发布。
- viewer 只能读取，写接口返回 403。
- 非成员不能读取项目页面。
- admin 可禁用用户或项目、取消发布并查看全局审计。

## AI 与 CRUD

- CRUD 请求应路由到确定性生成器。
- 生成页面必须带有效 Page 根节点、父子关系和数据源 contract。
- 事件/数据源 patch 必须通过 baseline 与 schema 校验。
- 候选未确认前不能修改编辑器 store。
- viewer 发起生成或应用候选应被拒绝。

## 发布安全

- 公开接口只返回发布快照。
- 取消发布、删除发布版本或禁用项目后的行为符合后端规则。
- 发布 runtime 不执行 custom JS，不使用编辑器 token。
- publisher metadata、缓存 tag 和 revalidate endpoint 正常。

## 远程物料契约与版本固定

- manifest 拒绝 `latest`、不兼容 schema、重复/冲突组件名、非法 entry 和非法 SRI。
- `createPageMaterialValidationContext` 只使用 manifest 元数据扩展 schema registry，不执行 JavaScript。
- 宿主对可信 `name@version` 幂等注册，并拒绝共享 React/ReactDOM/Ant Design 版本不兼容、bundle 声明不一致和运行时组件名冲突。
- owner 可安装、升级、启用、禁用和删除项目远程物料；editor/viewer 只能读取。
- 同一项目同一包仅一个启用版本，升级保留旧版本记录，同版本 manifest 摘要不可原地修改。
- 保存只固定组件树实际使用的远程依赖；`Page`、保存版本、发布版本和回滚版本保持依赖与 schema 同步。
- 发布与回滚拒绝未安装、已禁用、版本或 manifest 摘要不匹配的固定依赖。
- 项目升级后，既有公开接口仍返回 `publishedVersionId` 对应版本保存的旧 entry 与 integrity。

M4 的可重复验收由 `remote-material-contract.test.mjs`、`remote-material-host.test.mjs`、`remote-material-persistence.test.mjs`、`page-remote-material-lifecycle.test.mjs` 和 publisher runtime 测试覆盖。Prisma 结构变更还需运行 `npm run prisma:generate`、在 `apps/api-server` 下运行 `npx prisma validate --schema prisma/schema.prisma` 与 API 构建；启动已迁移的 PostgreSQL 和 API 后，`npm run smoke:remote-material` 验证真实权限、持久化、升级和公开快照不变。真实网络加载、SRI 浏览器失败和跨应用远程渲染属于 M5/M6 验收。

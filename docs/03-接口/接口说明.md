# API 说明

本文记录当前 API 分组、鉴权规则、关键请求和 schema contract。字段细节以 `apps/api-server` 的 controller、DTO、service 和各前端 feature API 为准。

## 基础信息

```text
本地后端：http://localhost:3000/api
前端配置：VITE_API_BASE_URL=http://localhost:3000/api
公开发布页配置：VITE_PUBLISHER_SITE_URL=http://localhost:5174
Next.js 发布页服务端配置：PUBLISHER_API_BASE_URL=http://localhost:3000/api
缓存失效配置：PUBLISHER_SITE_URL=http://localhost:5174，PUBLISHER_REVALIDATE_SECRET=<secret>
Token key：lowcode_editor_token
鉴权头：Authorization: Bearer <accessToken>
```

```json

  "statusCode": 400,
  "code": "PAGE_SCHEMA_INVALID",
  "message": "错误信息",
  "path": "/api/pages/1",
```

## 鉴权边界

公开接口：

- `POST /api/auth/register`
- `POST /api/auth/login`
- `GET /api/public/pages/:publicId`
- `POST /api/revalidate/published-page`（Next.js 发布页运行时内部接口）

受保护接口：

- 项目、页面、版本、发布、素材、模板等业务接口需要 JWT。
- 管理员接口需要 JWT + `AdminGuard`。

项目角色：

| 角色 | 能力 |
| --- | --- |
| owner | 管理项目、成员、审计、页面、版本、发布、数据源模型 |
| editor | 读项目，创建/保存/发布/回滚页面，维护数据源模型 |
| viewer | 只读项目、页面、版本和数据源模型 |

## Remote Materials API

远程物料配置属于项目级可信代码清单。owner 负责安装、升级、启用、禁用和删除；editor/viewer 只能读取。API 只校验并保存 manifest 元数据，不下载或执行 entry JavaScript。

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/projects/:projectId/remote-materials` | 项目成员 | 列出项目保留的所有远程物料版本 |
| POST | `/api/projects/:projectId/remote-materials` | owner | 安装新版本或幂等启用同一不可变版本 |
| PATCH | `/api/remote-materials/:id` | owner | 使用 `status=enabled/disabled` 切换当前版本 |
| DELETE | `/api/remote-materials/:id` | owner | 删除项目物料版本记录，不修改既有发布快照 |

安装请求：

```json
{
  "manifestUrl": "https://cdn.example.com/customer/1.2.0/manifest.json",
  "manifest": {
    "protocolVersion": "1",
    "name": "@portfolio/customer-materials",
    "version": "1.2.0",
    "entry": "./customer-materials.iife.js",
    "integrity": "sha384-...",
    "schemaVersion": "1.0.0",
    "dependencies": {
      "react": "^18.3.1",
      "reactDom": "^18.3.1",
      "antd": "^5.20.0"
    },
    "materials": [
      {
        "name": "CustomerSummary",
        "displayName": "客户摘要",
        "category": "data",
        "allowedParents": ["Page", "Container"]
      }
    ]
  }
}
```

响应会把相对 entry 解析为绝对地址，并返回 `id/projectId/status/createdAt/updatedAt` 和规范化后的完整 `PageMaterialDependency` 字段。同一项目同一包只能有一个启用版本；安装新版本会保留并禁用旧版本。已存在的 `name + version` 只有 manifest 摘要完全一致时才能幂等重新启用，否则返回 `409 REMOTE_MATERIAL_CONFLICT`。

协议、固定版本、schema、SRI、父子声明或 URL 不合法时返回 `400 REMOTE_MATERIAL_MANIFEST_INVALID`；内置组件名或其他启用远程包组件名冲突时返回 `409 REMOTE_MATERIAL_CONFLICT`。发布或回滚引用的固定版本未安装、已禁用或摘要不匹配时返回 `409 PAGE_MATERIAL_DEPENDENCY_INVALID`。

## Pages API

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/projects/:projectId/pages` | 项目成员 | 页面列表 |
| POST | `/api/projects/:projectId/pages` | owner/editor | 创建页面 |
| GET | `/api/pages/:id` | 项目成员 | 页面详情 |
| PATCH | `/api/pages/:id` | owner/editor | 更新页面和 schema |
| DELETE | `/api/pages/:id` | owner/editor | 删除页面 |
| GET | `/api/pages/:id/versions` | 项目成员 | 版本列表 |
| POST | `/api/pages/:id/rollback` | owner/editor | 回滚到版本 |
| DELETE | `/api/pages/:id/versions/:versionId` | owner/editor | 删除未被公开页面引用的版本记录 |
| POST | `/api/pages/:id/publish` | owner/editor | 发布页面 |
| POST | `/api/pages/:id/unpublish` | owner/editor | 取消发布 |
| GET | `/api/public/pages/:publicId` | 公开 | 读取发布快照 |

新建页面的 `revision` 从 `1` 开始。`PATCH /api/pages/:id` 必须提交读取页面时取得的 `expectedRevision`；更新成功后 `revision` 原子递增。若页面已被其他编辑者、其他窗口或回滚操作更新，接口返回 `409 PAGE_DRAFT_CONFLICT`，不覆盖当前草稿、不创建 `PageVersion`。只修改名称或路由的 PATCH 同样遵守 revision，但不创建页面版本。

当前 `publishedVersionId` 指向的版本不能直接删除；接口返回 `409 PAGE_VERSION_IN_USE`。取消发布会先清空该引用，随后版本才能删除。

发布和取消发布成功后，后端会在配置了 `PUBLISHER_SITE_URL` 和 `PUBLISHER_REVALIDATE_SECRET` 时调用 Next.js 发布页运行时：

```http
POST /api/revalidate/published-page
x-revalidate-secret: <PUBLISHER_REVALIDATE_SECRET>
content-type: application/json

{ "publicId": "<publicId>" }
```

该接口由 `apps/publisher-web` 提供，用于失效 `published-page:<publicId>` 缓存 tag。未配置缓存失效地址或调用失败时，发布/取消发布主流程不失败，但审计 metadata 会记录 revalidate 结果。

创建页面：

```json
{
  "expectedRevision": 1,
  "name": "首页",
  "routePath": "/home"
}
```

保存页面：

```json
{
  "name": "首页",
  "routePath": "/home",
  "schema": {
    "schemaVersion": "1.0.0",
    "pageId": 1,
    "components": [
      {
        "id": 1,
        "name": "Page",
        "props": {},
        "desc": "页面",
        "children": []
      }
    ],
    "metadata": {
      "updatedAt": "2026-04-28T00:00:00.000Z"
    }
  }
}
```

保存成功响应包含递增后的 `revision`，客户端必须以该值作为下一次保存基线。服务端根据组件树和项目当前启用的远程物料构建动态 schema registry，并把页面实际使用的完整依赖写入响应的 `materialDependencies`；客户端不能自行提交或覆盖该字段。发布前的自动保存使用同一规则；发生 revision 冲突时不得继续发布。发布或取消发布只改变发布状态，不递增草稿 revision。

`GET /api/public/pages/:publicId` 额外返回发布版本自己的 `materialDependencies`，每项固定 `packageName/version/manifestUrl/entry/integrity/schemaVersion/dependencies/materials`。公开读取不查询项目当前启用版本，因此项目后续升级、禁用或删除配置不会改写已经发布的页面快照。

回滚：

```json
{
  "versionId": 1
}
```

## Data Source Models API

数据源模型是项目级“外部 API + 字段映射 + 生成选项”配置，用来生成前端 CRUD 页面 schema。平台只保存配置，不保存用户业务记录，不生成业务数据库表，也不代理外部业务数据接口。

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/projects/:projectId/data-source-models` | 项目成员 | 数据源模型列表 |
| POST | `/api/projects/:projectId/data-source-models` | owner/editor | 创建数据源模型 |
| GET | `/api/data-source-models/:id` | 项目成员 | 数据源模型详情 |
| PATCH | `/api/data-source-models/:id` | owner/editor | 更新数据源模型 |
| DELETE | `/api/data-source-models/:id` | owner/editor | 删除数据源模型 |

创建或更新核心结构：

```json
{
  "name": "用户",
  "key": "user",
  "primaryField": "id",
  "listApi": {
    "url": "/external/users",
    "method": "GET",
    "responseDataPath": "data.items",
    "responseTotalPath": "data.total"
  },
  "detailApi": {
    "url": "/external/users/{{ variables.recordId }}",
    "method": "GET",
    "responseDataPath": "data"
  },
  "createApi": {
    "url": "/external/users",
    "method": "POST"
  },
  "updateApi": {
    "url": "/external/users/{{ variables.recordId }}",
    "method": "PATCH"
  },
  "fields": [
    {
      "key": "name",
      "label": "姓名",
      "type": "text",
      "required": true,
      "listVisible": true,
      "formVisible": true,
      "detailVisible": true
    }
  ]
}
```

校验边界：

- `key` 在项目内唯一，只支持小写字母、数字和下划线，且以字母开头。
- `fields` 不能为空，字段 `key` 不能重复，字段类型只支持 `text/textarea/number/boolean/date/select`。
- API URL 仅描述外部接口地址和模板；实际业务数据请求由生成页运行态的数据源或 HTTP action 执行。
- viewer 可读取配置，但不能创建、更新或删除。

## AI Page Builder API

AI 页面搭建接口需要 JWT，并且只允许项目 `owner/editor` 使用。接口只返回低代码 Page schema 草稿，不生成 React/Vue/HTML 源码，也不会把模型 API key 暴露给前端。服务端未配置 `AI_PROVIDER_API_KEY` 时，会返回本地规则生成的可编辑草稿，并在 `warnings` 中说明降级原因。

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/projects/:projectId/ai/page-generation` | owner/editor | 基于项目上下文生成页面草稿 |
| POST | `/api/pages/:pageId/ai/page-generation` | owner/editor | 基于当前页面上下文生成页面草稿 |
| POST | `/api/projects/:projectId/ai/agent-runs` | owner/editor | 基于项目上下文创建 AI agent run |
| POST | `/api/pages/:pageId/ai/agent-runs` | owner/editor | 基于当前页面和组件树创建 AI agent run |
| GET | `/api/ai/agent-runs/:runId` | 项目成员 | 读取 agent run 状态和候选结果 |
| POST | `/api/ai/agent-runs/:runId/cancel` | 有编辑权限的发起者或项目 owner | 取消 queued/running 任务；重复取消幂等，其他状态 409 |
| POST | `/api/ai/agent-runs/:runId/confirm` | 任务发起者或项目 owner | 确认当前候选；只记录接受决策，不保存页面 |
| POST | `/api/ai/agent-runs/:runId/reject` | 任务发起者或项目 owner | 拒绝当前候选，可选记录拒绝原因 |
| GET | `/api/pages/:pageId/ai/agent-runs` | 项目成员 | 当前用户在此页面最近 20 个任务，按创建时间倒序 |
| GET | `/api/projects/:projectId/ai/agent-runs` | 项目成员 | 当前用户最近 20 个项目级任务（pageId 为空） |

Agent 创建接口返回 HTTP **202** 和 `{ "runId": "...", "status": "queued" }`，不等待模型生成。客户端随后查询 `/api/ai/agent-runs/:runId` 获取下述候选快照。同页面已有 queued/running 任务返回 409（数据库部分唯一索引保障）；每用户每分钟最多接收 12 次任务，超过返回 409。

GET 快照包含 `lastSequence`、递增 `events[].sequence`、可选 `savedVersionId` 和 `candidateExpiresAt`。快照及事件在同一任务行锁下读取。历史接口返回 `{ id, status, createdAt }[]`，仅发现当前用户自己的任务，不恢复未保存的浏览器草稿。单任务 GET 仍检查当前项目权限。

当前使用 1.5 秒轮询；排队、开始和恢复事件即时持久化，生成器内部工具轨迹在结果事务中统一写入，尚非实时工具进度流。SSE 和定时过期/清理任务尚未接入。前端会在请求 confirm 前检查 24 小时有效期、草稿 baseline 与 schema；只有服务端返回 `accepted` 才应用至 editor store，随后仍需用户手动保存。

候选决策请求：

```json
{ "candidateId": "candidate-id" }
```

```json
{
  "candidateId": "candidate-id",
  "reason": "可选拒绝原因"
}
```

回滚成功会替换 `Page.schema`、创建 `source=rollback` 的新版本并递增页面 `revision`，从而使仍持有旧草稿基线的客户端在保存时收到冲突。

候选决策规则：

- 只有任务发起者或项目 owner 可确认/拒绝；viewer 和其他 editor 不可代为决策。
- 同一决策幂等；相反决策、候选 ID 不匹配或状态不允许时返回 409。
- 确认只将 run 迁移为 `accepted` 并记录 `ai.agent.confirm` 审计，不修改 `Page.schema`、不创建 `PageVersion`。
- 拒绝将 run 迁移为 `rejected` 并记录 `ai.agent.reject` 审计；可选 reason 保存在决策快照和审计 metadata 中。
- 服务端使用数据库时间检查 `candidateExpiresAt`；过期时先持久化 `expired` 状态、事件与 `ai.agent.expire` 审计，再返回 409。

安全规则：

- AI 输出写入编辑器前必须通过物料白名单、组件树、父子关系和事件动作校验。
- AI 默认不得生成 `custom` action 或可执行脚本。
- AI agent run 会返回 `routeDecision`，用于说明自然语言请求被识别为 `crud-page`、`free-page`、`edit-selected`、`style-polish`、`bind-data-source`、`add-event-action` 或 `fix-page-issue`，以及本次选择的工具、置信度、命中原因和降级说明。
- AI agent 只能调用服务端白名单工具；工具只返回候选 schema、候选 patch 或校验结果，不直接保存、发布或访问任意外部系统。
- AI agent 的 CRUD 工具只返回候选 Page schema/components 和 CRUD 元信息，不直接保存数据源模型、创建页面或调用外部业务接口。
- AI agent 候选 patch 必须由用户确认后才能写入编辑器，应用时会重新校验 stale baseline、目标组件、父子关系和安全规则。
- 公开发布页继续通过 `<Preview allowCustomJS={false} />` 禁止自定义 JS。
- HTTP action 仍受现有 URL、headers、body 和 allowed origins 运行态规则约束。

## Admin API

统一前缀：`/api/admin`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/overview` | 平台概览 |
| GET | `/api/admin/users` | 用户列表 |
| PATCH | `/api/admin/users/:id/status` | 启用/禁用用户 |
| GET | `/api/admin/projects` | 项目列表 |
| PATCH | `/api/admin/projects/:id/status` | 启用/禁用项目 |
| GET | `/api/admin/published-pages` | 已发布页面 |
| POST | `/api/admin/pages/:id/unpublish` | 管理员取消发布 |
| GET | `/api/admin/audit-logs` | 全局审计 |

管理员操作会写入审计日志。禁用项目会阻断普通用户访问，并取消该项目下公开发布页。

## Schema Contract

组件节点：

```ts
{
  id: number;
  name: string;
  props: any;
  styles?: CSSProperties;
  desc: string;
  children?: Component[];
  parentId?: number;
}
```

页面 schema：

```ts
{
  schemaVersion: CURRENT_SCHEMA_VERSION;
  pageId?: number;
  components: Component[];
  metadata?: Record<string, unknown>;
}
```

关键规则：

- 前端保存前校验 `components`。
- 后端创建、保存、发布、回滚前都会先迁移再校验。
- AI 生成结果写入编辑器前会先通过 `validateAiGeneratedComponents` 校验，再由用户确认应用。
- `Page.schema` 是当前草稿。
- `Page.revision` 是当前草稿的乐观并发版本；页面 PATCH 使用 `expectedRevision` 原子比较并递增。
- `PageVersion.schema` 是保存、回滚或发布时的快照。
- 公开页只读取 `publishedVersionId` 指向的版本快照。
- Next.js 公开发布页运行时同样只读取公开接口返回的发布快照，不直接访问数据库或 Prisma。

# 项目架构说明

## 总体结构

```text
apps/
  editor-web/       Vite + React + Zustand + Ant Design
  publisher-web/    Next.js App Router
  api-server/       NestJS + Prisma
  remote-material-example/  独立远程物料 IIFE 与 manifest
packages/
  lowcode-schema/   schema 类型、迁移、校验和生成规则
  lowcode-runtime/  无状态渲染、事件执行和生产物料
infra/              Docker Compose、Nginx 和运维脚本
```

```text
editor-web ──HTTP──> api-server ──Prisma──> PostgreSQL
publisher-web ─HTTP─> api-server

editor-web ───────┐
publisher-web ────┼──> lowcode-runtime ──> lowcode-schema
api-server ───────┘                     └─> lowcode-schema
remote-material-example ──IIFE/register──> lowcode-runtime host
```

## 编辑器应用

`apps/editor-web/src` 按职责分为：

- `app/`：应用装配、会话恢复、视图切换和 provider。
- `features/auth/`：登录注册及用户类型。
- `features/projects/`：项目、页面、成员、素材和数据源模型。
- `features/admin/`：平台治理后台。
- `features/editor/`：组件树、画布、设置面板、物料和设计态预览。
- `shared/`：业务无关的 HTTP client 与通用组件。

业务 API 和类型归所属 feature。跨 feature 依赖只能通过目标 feature 的 `index.ts`；编辑器 store 给 app 层使用的最小入口是 `features/editor/public.ts`。

### 编辑器状态

`useComponentsStore` 持有：

- `components`：页面组件树。
- `curComponentId / curComponent`：当前选择。
- `mode`：`edit` 或 `preview`。
- `pastComponents / futureComponents`：仅内存中的撤销重做历史。

页面根节点必须是 `Page`。组件节点使用 `{ id, name, props, styles, desc, children?, parentId? }`。

组件树修改使用结构共享：只复制目标节点及其祖先链，未变化分支保持引用稳定；撤销/重做历史保存不可变树引用，不重复深拷贝历史快照。画布将树订阅和选择态订阅分开，并为递归节点提供 `React.memo` 边界。返回多个 Zustand 字段的 selector 使用 `shallow`；`useMaterialDrop` 只订阅稳定 action，拖放判定时通过 store 快照读取最新组件树。可复现数据见 `docs/06-测试与验收/编辑器状态订阅性能基准.md`。

### 设计态渲染

- registry 位于 `features/editor/registry/`，组合物料元数据、setter、事件、方法和 dev/prod 实现。
- dev 物料位于 `features/editor/materials/`，负责拖拽、选择和编辑反馈。
- `components/EditArea` 递归渲染 dev 物料。
- `components/Preview` 把当前草稿交给 `@lowcode/runtime`，并注入编辑器允许的策略。
- prod 物料只存在于 `packages/lowcode-runtime`，编辑器不维护重复实现。
- `remote-materials/` 在浏览器读取项目当前启用物料，安装宿主并运行共享 loader；成功后批量合并远程 dev/prod、setter、event、method 和父子接收关系，失败时画布保留稳定占位。

## Schema 与运行时

`@lowcode/schema` 是跨应用协议层，负责：

- 页面和事件类型。
- 旧 schema 迁移。
- 组件树、父子关系和物料白名单校验。
- 动作 URL、HTTP action 和安全表达式规则。
- 数据源模型、CRUD 生成和 AI patch 契约。
- 远程物料 manifest、页面依赖快照和动态 schema registry 契约。

`@lowcode/runtime` 是无状态执行层，负责：

- 根据传入组件树渲染 prod 物料。
- 运行 toast、url、confirm、condition、http、变量和组件控制动作。
- 执行页面数据源并维护单次运行态数据。
- 通过 policy 决定 API 地址、允许域名、token、custom JS 和错误上报。
- 提供远程物料宿主注册协议，由宿主共享唯一 React、ReactDOM 和 Ant Design 实例，并校验协议、schema、共享依赖和组件名冲突。
- 提供客户端远程物料 loader，隐藏 manifest 获取、固定快照复核、HTTPS/本地协议限制、origin allowlist、entry 字节级 SRI、`<script>` 注入、超时、错误映射和 Promise 去重。

运行时不读取编辑器 Zustand store，也不直接访问后端或数据库。M4 建立注册协议，M5 提供可独立发布的示例产物，M6 在 editor 与 publisher 浏览器客户端接入 loader；NestJS 和 Next.js 服务端仍只处理元数据，不执行远程 JavaScript。

## 示例远程物料

`apps/remote-material-example` 是独立 workspace，通过 Vite library mode 输出 `remote-material-example.iife.js` 和 `manifest.json`。构建结束后根据最终 entry 字节生成 SHA-384 SRI；React、ReactDOM 和 Ant Design 只声明为 peer dependency，运行时从 `window.__LOWCODE_MATERIAL_HOST__.shared` 获取宿主实例。

示例 `CustomerMetricCard` 包含 hook、可配置属性、子节点、动作事件和 `reset` 方法。bundle 同时提供独立 dev 包装组件及 setter/event/method 描述；项目启用该固定版本且 origin 进入编辑器 allowlist 后，M6 loader 会把它注册进物料区、画布和预览。本地静态服务继续只用于模拟带 CORS 的 OSS/CDN。

## 发布站

`apps/publisher-web` 只处理匿名公开页面：

1. `/publish/[publicId]` 调用 API 的公开快照接口。
2. `preparePublishedPageSnapshot` 使用发布版本固定的物料依赖构建动态 registry，再迁移并校验快照。
3. 服务端生成 metadata、canonical URL、favicon 和缓存 tag。
4. 服务端把 `PUBLISHER_REMOTE_MATERIAL_ALLOWED_ORIGINS` 解析结果作为普通 prop 传给客户端，不获取 entry。
5. 客户端对发布版本自己的固定依赖完成 manifest/SRI/宿主注册；全部就绪后才通过 `@lowcode/runtime/client` 渲染页面，失败时显示访客可理解的错误页。
6. runtime policy 固定 `allowCustomJS=false`，不提供当前用户 token。

发布站不读取 editor-web 或 api-server 的源码，也不直连 Prisma。

## API 与数据库

`apps/api-server/src` 分为：

- `modules/`：auth、projects、pages、remote-materials、assets、templates、data-source-models、ai、admin、audit、health。
- `common/`：guard、decorator、filter、错误和日志。
- `config/`：环境变量校验。
- `infrastructure/database/`：NestJS 的 Prisma 接入。

`apps/api-server/prisma/` 是 Prisma CLI 的唯一事实来源，包含 `schema.prisma` 与 migrations。

核心关系：

```text
User ──owns──> Project ──contains──> Page ──has──> PageVersion
User <──ProjectMember──> Project
Project ──contains──> Asset / PageTemplate / ProjectDataSourceModel / AuditLog
Project ──contains──> ProjectRemoteMaterial
Page ──publishedVersionId──> PageVersion
Page / PageVersion ──pins──> materialDependencies(JSON)
```

项目访问统一通过 `ProjectAccessService`。owner/editor 可写，viewer 只读；管理员能力由额外 guard 和 service 校验。

## 保存与发布

```text
编辑器草稿
  -> migratePageSchema
  -> 读取项目已启用的规范化远程物料元数据
  -> 构建内置 + 远程动态 schema registry
  -> validateComponentTree
  -> PATCH /pages/:id(expectedRevision)
  -> 原子比较并递增 Page.revision
  -> 更新 Page.schema 与实际使用的 materialDependencies；冲突时返回 409 且不覆盖
  -> 新建 PageVersion(source=save)，复制固定依赖

POST /pages/:id/publish
  -> 锁定草稿并校验固定物料版本仍启用
  -> 使用草稿自己的固定依赖重新校验 schema
  -> 新建 PageVersion(source=publish)，复制固定依赖
  -> Page.publishedVersionId 指向该版本
  -> 记录 AuditLog
  -> 通知 publisher 失效缓存
```

公开读取始终返回 `publishedVersionId` 对应的版本，不返回后来修改但尚未发布的草稿。

项目物料升级只改变项目当前启用版本，不原地修改旧版本记录，也不修改任何 `PageVersion.materialDependencies`。公开页面即使在项目升级、禁用或删除物料记录后，仍返回发布版本保存的 manifest、entry 与 integrity；后续重新发布或回滚则要求目标固定版本仍在项目中启用。

页面草稿使用 `Page.revision` 做乐观并发控制。普通保存和页面信息更新都必须命中 `id + expectedRevision`；回滚替换 schema 后递增 revision。发布与取消发布只管理公开快照引用，不改变草稿 revision。

## 数据源与 AI

数据源模型只保存外部 API、字段映射和生成选项。CRUD 生成器产出普通 Page schema，继续使用 registry、事件动作、保存和发布链路。

AI 调用只经过 API 的模型网关。生成结果是 schema 或 patch，必须先完成上下文读取、候选生成、校验、摘要与预览，用户确认后才能写入 store。

## 架构验证

- `npm run check:architecture`：应用、feature、shared 和 package 依赖方向。
- `npm run check:editor-props`：registry setter 与 dev/prod 消费契约。
- `npm run test`：schema、runtime、发布和后端规则。
- `npm run test:e2e:editor`：编辑器主交互。

长期决策及原因记录在 `docs/adr/`。

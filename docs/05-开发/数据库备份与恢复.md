# 数据库备份与恢复

数据库包含用户、项目、页面草稿、版本、发布快照、素材元数据和审计日志。备份只有经过恢复验证才可视为有效。

## 脚本

```text
apps/api-server/scripts/database/backup-postgres.ps1
apps/api-server/scripts/database/restore-postgres.ps1
```

## 本机 PostgreSQL 工具

```powershell
$env:DATABASE_URL="postgresql://postgres:postgres@localhost:5432/lowcode_editor?schema=public"
powershell -ExecutionPolicy Bypass -File apps/api-server/scripts/database/backup-postgres.ps1
```

恢复：

```powershell
powershell -ExecutionPolicy Bypass -File apps/api-server/scripts/database/restore-postgres.ps1 `
  -BackupFile backups/lowcode-editor-20260509-120000.dump
```

`-Clean` 会清理目标数据库中的旧对象，只能在确认目标连接后使用。

## Docker Compose

在仓库根执行：

```powershell
$env:DATABASE_URL="postgresql://postgres:postgres@localhost:5432/lowcode_editor?schema=public"
powershell -ExecutionPolicy Bypass -File apps/api-server/scripts/database/backup-postgres.ps1 `
  -DockerComposeService postgres `
  -ContainerDatabaseUrl "postgresql://postgres:postgres@localhost:5432/lowcode_editor?schema=public"
```

使用生产 Compose 时，先通过 `-f infra/docker/docker-compose.prod.example.yml` 进入相应 Compose 项目，或在脚本执行前设置正确的 Compose 环境。

## 恢复演练

1. 新建隔离的测试数据库。
2. 恢复备份。
3. 临时修改 `apps/api-server/.env` 指向测试库。
4. 启动 API，验证登录、项目、页面版本、发布页和审计日志。
5. 记录恢复耗时和备份文件校验信息。

备份文件可能包含个人信息和页面内容，应按敏感数据保存，不得提交到 Git。

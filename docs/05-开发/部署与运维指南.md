# 部署与运维指南

## 部署资产

- `apps/editor-web/Dockerfile`
- `apps/publisher-web/Dockerfile`
- `apps/api-server/Dockerfile`
- `infra/docker/docker-compose.prod.example.yml`
- `infra/nginx/web.conf`
- `infra/scripts/check-production.ps1`

镜像使用 workspace 根作为 build context，但 Dockerfile 由各部署单元维护。

## 生产配置

```powershell
Copy-Item infra/docker/.env.prod.example infra/docker/.env
Copy-Item apps/api-server/.env.production.example apps/api-server/.env.production
```

至少替换：

- `POSTGRES_PASSWORD`
- `JWT_SECRET`
- `FRONTEND_ORIGIN`
- `PUBLISHER_SITE_URL`
- `PUBLISHER_REVALIDATE_SECRET`
- `VITE_PUBLISHER_SITE_URL`
- `VITE_LOWCODE_HTTP_ALLOWED_ORIGINS`
- AI provider key（启用远程模型时）

真实 `.env`、密钥和数据库备份不得提交到 Git。

## 首次部署

```powershell
docker compose --env-file infra/docker/.env -f infra/docker/docker-compose.prod.example.yml up -d --build
docker compose --env-file infra/docker/.env -f infra/docker/docker-compose.prod.example.yml ps
```

服务职责：

- `web`：Nginx 托管编辑器静态资源，并代理 `/api`。
- `publisher`：Next.js 匿名发布站。
- `server`：NestJS API，启动前执行 Prisma migration。
- `postgres`：持久化数据库。

上传文件使用 `uploads_data` volume，数据库使用 `postgres_data` volume。

## 发布检查

```powershell
powershell -ExecutionPolicy Bypass -File infra/scripts/check-production.ps1 -BaseUrl "https://editor.example.com"
```

至少人工确认：

1. 编辑器和 `/api/health` 可访问。
2. 用户能登录、创建项目、打开和保存页面。
3. owner/editor/viewer 权限符合预期。
4. 发布链接指向独立 publisher，匿名页面可访问。
5. 取消发布或禁用项目后公开页返回 404。
6. 管理后台和审计日志可用。

## 升级

1. 记录当前 commit。
2. 备份数据库。
3. 检查 `apps/api-server/prisma/migrations`。
4. 重新构建并启动 Compose。
5. 等待 API healthcheck。
6. 运行生产检查和主链路验收。

```powershell
docker compose --env-file infra/docker/.env -f infra/docker/docker-compose.prod.example.yml up -d --build
docker compose --env-file infra/docker/.env -f infra/docker/docker-compose.prod.example.yml logs -f server
```

## 排障

- API 404：检查 Nginx `/api/` 代理、`VITE_API_BASE_URL` 和 server healthcheck。
- CORS：检查 `FRONTEND_ORIGIN` 是否与编辑器真实 origin 完全一致。
- 发布页白屏：检查 publisher 日志、公开 API、发布快照校验和 revalidate secret。
- 上传丢失：检查 `uploads_data` volume 和 `UPLOAD_DIR`。
- 数据库失败：检查 Compose service 名、`DATABASE_URL` 和 migration 状态。

后端错误响应包含 `requestId`。排障时用它关联 server JSON 日志，不记录请求体或 Authorization。

## 回滚

应用回滚前先判断 migration 是否向后兼容。若数据库结构不兼容，必须使用发布前备份恢复，不能只切换代码镜像。

数据库备份与恢复见 `数据库备份与恢复.md`。

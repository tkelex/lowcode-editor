# 编码规范

## 通用原则

- 优先遵循现有模块边界和公开入口。
- 文件和函数只承担可描述的职责，避免通用 `model`、`state`、`utils` 堆积业务逻辑。
- 新抽象必须减少真实重复或复杂度。
- 用户可见错误要明确，日志不得包含 token、密码和连接串。

## 编辑器

- `app/` 只做装配，业务代码归 `features/`。
- feature 内 API 放 `api/`，类型放 `types.ts`，跨 feature 只从 `index.ts` 导入。
- `shared/` 不依赖 feature；`shared/api` 只保留业务无关 HTTP client。
- Zustand store 放 `stores/`，使用表达职责的名称。
- dev 物料根节点暴露 `data-component-id`，可接收子节点的物料使用 `useMaterialDrop`。
- 生产物料归 `@lowcode/runtime`，不在 editor 内复制 prod 实现。
- schema 进入 store 或后端前必须迁移和校验。

## API

- Controller 只处理协议和参数，Service 执行业务规则、权限和事务。
- DTO 使用 `class-validator`；环境变量在启动时校验。
- 项目数据访问复用 `ProjectAccessService`。
- 页面版本和发布快照变更复用 `PageLifecycleService`。
- 业务异常使用统一错误码，不向客户端暴露 Prisma 原始异常。

## 数据库

- Prisma schema 和 migrations 只放在 `apps/api-server/prisma/`。
- 生产环境不用 `db push` 替代 migration。
- model 变化同步 DTO、前端类型、接口文档和 smoke 测试。
- 审计、版本和发布快照等关键记录要在同一事务边界内维护。

## 共享包

- `lowcode-schema` 不依赖 app implementation。
- `lowcode-runtime` 保持无状态，通过 policy 注入环境能力。
- 对外导出变化要检查三个 app 的消费者和相关测试。

## 命名与验证

- 组件和类型使用 PascalCase，hook 使用 `useXxx`，API 函数使用动词开头。
- 不新增拼写错误兼容入口或无意义 re-export。
- 提交前按 `AGENTS.md` 的修改范围运行对应验证；目录改动额外运行 `npm run check:architecture`。
